═══════════════════════════════════════════════
CHANGES — API REFACTOR
═══════════════════════════════════════════════

1. Split server.ts into route modules
----------------------------------------------
Before: Single 500+ line server.ts with all routes, middleware, and logic.
After: Clean 40-line entry point that registers plugins and routes.

New route files:
- src/routes/chat.ts       — POST /v1/chat (RAG, billing, telemetry)
- src/routes/leads.ts      — POST /v1/leads (lead capture + email notification)
- src/routes/settings.ts   — GET/PUT /v1/settings
- src/routes/faqs.ts       — CRUD /v1/faqs
- src/routes/kb.ts         — Upload, list, delete knowledge base documents
- src/routes/analytics.ts  — GET /v1/analytics
- src/routes/monitoring.ts — Billing usage, observability, Prometheus metrics
- src/routes/widget.ts     — GET /widget.js

Each file is a Fastify plugin — isolated, testable, easy to find.

2. Added rate limiting
----------------------------------------------
New file: src/rate-limit.ts

- In-memory IP-based rate limiter as a Fastify plugin
- Configurable via RATE_LIMIT_RPM env var (default: 60 req/min)
- Returns 429 with x-ratelimit-limit, x-ratelimit-remaining, x-ratelimit-reset headers
- Auto-sweeps expired entries to prevent memory leaks

3. Standardised error responses
----------------------------------------------
New file: src/errors.ts

- Every error now returns: { error: string, code: string, details?: unknown }
- sendError() helper used across all routes
- Global error handler catches unhandled errors and 404s
- Auth errors use specific codes: AUTH_MISSING_TOKEN, AUTH_INVALID_TOKEN, AUTH_INSUFFICIENT_ROLE, etc.
- Validation errors use VALIDATION_ERROR with Zod details
- 500s never leak internal details to the client

4. Lead notification emails
----------------------------------------------
New file: src/notifications.ts

- sendLeadNotification() sends email to tenant's alertEmail when a lead is captured
- Uses nodemailer with SMTP config from env vars
- Gracefully skips if SMTP not configured or tenant has no alertEmail
- Fire-and-forget — doesn't block the API response
- Uses existing alertEmail field on Tenant model (no schema changes)

New dependency: nodemailer + @types/nodemailer

5. Deduplicated embeddings code
----------------------------------------------
Before: Identical embeddings code copy-pasted in apps/api and apps/worker.
After: Single source of truth in packages/shared/src/embeddings/.

- packages/shared/src/embeddings/types.ts   — EmbeddingVector, EmbeddingsProvider interface
- packages/shared/src/embeddings/openai.ts  — OpenAI embeddings provider
- packages/shared/src/embeddings/index.ts   — Factory, cosine similarity, vector parsing
- apps/api/src/embeddings/index.ts          — Re-exports from @bynle/shared
- apps/worker/src/embeddings/index.ts       — Re-exports from @bynle/shared

Deleted 4 duplicate files.

6. Widget tenant key injection
----------------------------------------------
Updated: apps/admin/app/dashboard/widget/page.tsx

- Pulls tenant's latest API key from DB using session
- Shows last 4 characters so they know which key (bynle_...ab12)
- Uses actual API_BASE_URL from env instead of hardcoded localhost
- Shows helpful message if no key exists yet

7. Cleaned up settings route
----------------------------------------------
PUT /v1/settings had the same field list written twice (update + create).
Simplified to use parsed.data directly with Prisma upsert.
